About & data

How Parramatta Explorer works, where the data comes from, and how to add more. Full detail lives in the docs/ folder of this project.

Prototype — illustrative data. This is a student prototype using clearly-labelled synthetic and public seed data. It is best-effort and community-verified, is not a substitute for official venue information, and is not endorsed, funded or procured by Council. In an emergency call 000.

Datasets used

  • Event listings — public City of Parramatta event pages and the Major Events and Festivals Strategy 2025–2030. Attribution required.
  • Venue and map geometry — OpenStreetMap, licensed ODbL. Attribution required.
  • Transport — Transport for NSW Open Data (stops, wheelchair boarding).
  • Access features — Council records where available; otherwise clearly marked as “requires confirmation”.
  • Community reports — created by participants; confirmed by other attendees rather than a moderator.

Every fact carries a source, a last-verified date and a status. Nothing is shown as fact unless a person has verified it. The “verified N days ago” figures in this prototype are example values counted from the moment you load a page.

How to add map data

  1. Add the venue to src/lib/data/seed.ts with a name, address and geo latitude/longitude.
  2. Add each access feature with its own geo, the needs it serves, and attributes — each with a source and a status (verified, requires confirmation, or missing).
  3. Run npm run build inside static-site/ to regenerate this site from that data.
  4. Keep the plain-text list in sync so every map has a non-visual equivalent (the build does this for you).

Working offline

After your first visit over https:// (or localhost), a service worker stores every page, the scripts, fonts and map library on your device, so the whole site opens with no signal. “Save this plan for offline” also stores map tiles around the venue. Where tiles aren't stored, the app shows the offline schematic map, and every map has a text list of the same information.

Where your information is stored

This static version has no server. Your display settings, need selections, reports, votes and ratings are kept in this browser's local storage and are not sent anywhere. That also means reports are not shared between people. A shared community board needs a backend (the Next.js app in this project has the API routes for it, backed by in-memory storage that resets on restart).

Responsible AI

AI helps turn messy text into structured access attributes, retrieve requirements from approved Council documents, and draft a risk register. Every AI output is labelled “AI-suggested — requires human confirmation” and cannot be published without an approver recorded. AI never makes a consequential decision autonomously, and any output can be removed, corrected, suspended and reviewed. In this prototype the AI step is a fixed stand-in, not a live model.

Privacy

  • Attendees: no name, email, health or disability information is collected. Any need profile stays in your browser.
  • Organisers: verified by a work-email link or invite code — no identity documents.
  • Reports: notes are screened to remove personal information and abusive language before they appear.

Council boundary

Partner: Council hosts the readiness workflow and owns verified data. Facilitate: distribute the plan through existing event channels. Advocate: for access conditions Council does not control (station lifts, private venues), the tool produces an advocacy brief for the relevant operator.
